## 설계가 실제로 바뀐 지점

행사 조건이 구체화되면서 초기 가정이 여러 번 뒤집혔다. 기록해 둔다.

| 항목 | 초기 설계 | 최종 | 이유 |
|---|---|---|---|
| 참가 인원 | 500명 | **300명+ / 동시 20명** | 실제 방문 규모 확인 |
| QR 카드 | 유령당 3장 (60장) | **유령당 1장 (20장)** | 동시 20명이면 줄이 안 선다 |
| 등급 해금 | Day1 Common → Day3 Mythic | **매일 20종 전부 활성** | 매일 다른 학생이 온다. 첫날 학생이 Epic을 영영 못 봄 |
| 랭킹 | 3일 누적 | **당일 랭킹** | 누적은 마지막 날 참가자가 절대 유리 |
| QR 위치 | 고정 | **매일 변경** | 전날 학생이 위치를 알려주는 것 차단 |
| 인프라 | Supabase → Firebase | **Cloudflare** | 무료 한도·콜드스타트·중단 위험 비교 |
| 닉네임 | 2~8자, 중복 허용 | **2~12자, 중복 불가** | 추가 사양 §34 |
| 중복 발견 보상 | XP 0 | **XP +10 / 코인 +2** | 추가 사양 §40 |

## 폐기된 문서를 남겨 두는 이유

Firebase 문서(02)에는 **무료 한도 실측 계산**이 들어 있다.
"기존 설계를 그대로 옮기면 첫날 읽기 한도를 241% 초과한다"는 계산과,
Hosting 전송량 때문에 **유령 이미지를 PNG로 만들면 안 되는 근거**가 여기 있다.

이 제약은 Cloudflare로 옮긴 뒤에도 **에셋 발주서에 그대로 살아 있다.**
숫자의 출처를 확인하고 싶을 때 참고할 것.
